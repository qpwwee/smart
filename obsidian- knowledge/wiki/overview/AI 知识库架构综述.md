# AI 知识库架构综述

> 本项目知识库架构的全景图

## 设计理念

基于 [[Andrej Karpathy]] 提出的 [[LLM Wiki 方法论]] [[LLM Wiki 方法论]]，构建一个可自我完善的个性化 AI + 知识库系统。

核心原则：**知识编译一次，持续更新，复利增长。**

## 数据流

### Ingest 流程
```
新资料 → raw/ → OpenCode 读取 → 生成摘要页 → 更新实体/概念页 → 更新 index.md → 记录 log.md
```

### Query 流程
```
人类提问 → 向量搜索 → 读取相关页面 → 综合回答 → 好答案回存 Wiki
```

### Lint 流程
```
触发 Lint → 扫描所有页面 → 发现问题 → 修复/建议 → 记录 log.md
```

## 关系图谱链接方法论

在 [[LLM Wiki 方法论]] 中，**链接方向即知识流向**：

- **是-关系**：子类 → 父类（[[神经网络]] → [[机器学习]]）
- **使用-关系**：工具 → 领域（Python → 数据分析）
- **基于-关系**：实现 → 理论（[[Transformer]] → [[大语言模型]]）
- **影响-关系**：原因 → 结果（注意力机制（Attention） → [[Transformer]]）

图谱的密度和连通性反映了知识库的健康度和深度。

## 自我改善闭环

```
人类提问 → OpenCode 回答 → 检查 Wiki 完整性
  ↓                              ↓
Wiki 不完整 → 建议补充 → 人类提供新资料
  ↓                              ↓
OpenCode Ingest → 更新图谱 → 下次回答更准确
```

## 性能优化要点

- **查询时直接 simple_vector_search**，不预读 index.md 或 TheSchema.md
- **只读 top 2-3 搜索结果**，避免冗余 read_file 调用
- **index.md 和 TheSchema.md 仅在 Ingest/Lint 时读取**
- **MCP 连接顺序**：obsidian（最快，SSE 远程）→ local-knowledge-base → my-kb

## 合成上限监控

LLM Wiki 模式的理论上限约 **100-200 页**（称为合成上限 Synthesis Horizon）。当前页面数：52（2026-05-13）。

当接近上限时：
- **100 页**：评估是否需要引入 qmd 搜索引擎作为 RAG 补充层
- **150 页**：考虑将稳定概念归档为"只读引用层"，wiki 仅维护活跃概念
- **200 页**：启动分层迁移——wiki 编译高频知识，RAG 检索低频知识

详见 [[wiki/synthesis_horizon_tracker]]。
