# 多智能体系统

> 由多个 AI 智能体组成的协作系统，通过编排器协调各智能体完成单一智能体难以独立处理的复杂任务。2026 年业界已收敛于编排器+子智能体模式。

## 定义

多智能体系统（Multi-Agent System，MAS）是由多个相互作用的 [[智能体]] 组成的计算系统，这些智能体共享环境并可能具有不同的目标、能力或知识。核心思想：**让合适的智能体做合适的事。**

在现代 AI 语境下，多智能体系统通过标准化通信协议（如 [[A2A 协议]] 和 [[MCP Server]]）协调各智能体，使系统能够处理单一智能体无法独立完成的复杂任务。

## 核心机制

### 协作模式
- **任务分解**：将复杂任务分配给多个智能体
- **信息共享**：智能体间共享知识和状态
- **协调机制**：避免冲突，优化资源配置

### 竞争模式
- **拍卖机制**：智能体通过竞标获取任务
- **博弈论**：智能体在竞争中进行策略博弈
- **市场机制**：模拟经济系统的资源分配

### 通信协议
- **点对点通信**：智能体间直接消息传递
- **广播通信**：向所有智能体发布信息
- **黑板系统**：共享信息空间

## 典型应用

- **机器人团队**：协调多个机器人完成任务
- **交通系统**：优化交通信号和路线规划
- **分布式传感**：多节点协作感知环境
- **智能电网**：协调能源分配和调度

## 2026 年行业共识

### 编排器+子智能体（业界标准）

| 模式 | 描述 | 状态 |
|------|------|------|
| **编排器+子智能体** ⭐ | 编排器拥有完整对话上下文，负责任务分解和分配；子智能体短暂存在，完成子任务后返回压缩摘要 | 业界标准 |
| **GroupChat（点对点协作）** ❌ | 所有智能体自由通信，信息冗余、协调开销大 | 已被证明低效，逐渐淘汰 |

### 主流实现对比

| 平台 | 模式 | 特点 |
|------|------|------|
| Anthropic Claude Code | Agent 团队模式 | 层级式编排，子智能体按需创建 |
| OpenAI Agents SDK | 层级式编排 | 内置编排器 + 专用 Agent |
| [[OpenCode]] Agent Teams | 扁平团队架构 | 1 主导 + N 队友，同一模型降低加载开销 |

## 对比：单一 vs 多智能体

| 维度 | 单一智能体 | 多智能体系统 |
|------|-----------|-------------|
| **架构复杂度** | 低，一个 Agent 做所有事 | 高，需要编排+通信+协调 |
| **任务并行能力** | 串行处理 | 可并行（约 +16% 吞吐提升） |
| **失败率** | 低（约 20%） | 高（41-87%，79% 源于协调失败） |
| **额外 Token 开销** | 无 | 集中式约 +285%，独立式约 +58% |
| **调试难度** | 低，端到端追踪 | 高，需要追踪跨 Agent 通信 |
| **专业分工** | 一个模型胜任所有子任务 | 各 Agent 可专精不同领域 |
| **可扩展性** | 受限于模型上下文窗口 | 可通过增加 Agent 扩展 |
| **适用场景** | 大多数单域任务 | 可并行、大量只读、多专家域 |

### 选型决策树

```
任务复杂度高？
├─ 否 → 单一智能体（默认选择，约 80% 场景）
└─ 是 → 可拆分为独立子任务？
        ├─ 否 → 单一智能体
        └─ 是 → 子任务需要不同专长？
                ├─ 否 → 单一智能体（并行批处理即可）
                └─ 是 → 多智能体系统（编排器+子智能体）
```

## 通信协议

多智能体系统依赖三类协议完成通信：

| 协议 | 通信方向 | 角色 |
|------|---------|------|
| [[A2A 协议]] | 智能体↔智能体（水平） | 任务委派与协作 |
| [[MCP Server]] | 智能体→工具（垂直） | 工具调用与资源访问 |
| REST API | 客户端↔服务器 | 基础设施传输 |

详见 [[多智能体系统与协议栈综述]]。

## 在本项目中的配置

OpenCode 使用扁平团队架构：

| 智能体 | 类型 | 职责 | 模型（当前） |
|--------|------|------|-------------|
| **build（默认）** | 主导 Agent | 综合查询 + Wiki 维护 | deepseek-v4-flash-free（云端） |
| **query-agent** | 子智能体 | 知识查询专家 | deepseek-v4-flash-free（云端） |
| **lint-agent** | 子智能体 | 健康检查专家 | deepseek-v4-flash-free（云端） |
| **ingest-agent** | 子智能体 | 知识摄入专家 | deepseek-v4-flash-free（云端） |

> 📝 **历史模型**：此前配置使用 `gemma4:e4b`（build）和 `gemma4-cn`（子智能体），但本地推理模型已全部从 [[Ollama]] 卸载，当前所有 Agent 统一使用云端对话模型。

### 设计原则
- 用户交互由单一 build 主导，保证上下文连贯性
- 后台任务（lint/ingest）由子智能体并行处理，不打断主对话
- 子智能体返回压缩摘要，避免编排器上下文膨胀
