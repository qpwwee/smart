# 知识编译

> 核心洞察：不要让 LLM 在查询时理解原始文档，而是提前编译成结构化知识

## 定义

知识编译是 [[LLM Wiki 方法论]] 的核心机制，类比编程语言的编译器：

```
源代码 (.py) → 编译 → 字节码（已优化） → 执行 → 结果
原始文档 (PDF) → Ingest → Wiki 页面（结构化） → Query → 答案
```

## 核心原则

1. **编译一次，持久存在** — 知识不需要每次查询时重新推导
2. **持续更新** — 新资料加入时增量更新，不是全量重建
3. **复利增长** — 每次编译都让知识库更丰富

## 与 RAG 的本质区别 [[RAG vs 知识编译]]

- RAG = 每次查询时从原始文档临时检索（类似解释执行）
- 知识编译 = 提前把原始文档编译成结构化知识（类似编译执行）

## 在本项目中的实现 [[LLM Wiki 方法论]]

- [[OpenCode]] 充当「知识编译器」 影响-关系（OpenCode**影响**了知识编译）
- `raw/` 目录中的原始文档是「源代码」
- `wiki/` 目录中的 Markdown 文件是「编译产物」
- TheSchema.md（配置文件） 是「编译规则」
