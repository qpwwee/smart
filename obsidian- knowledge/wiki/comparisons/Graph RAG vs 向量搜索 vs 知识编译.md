# Graph RAG vs 向量搜索 vs 知识编译

> 三种技术在 2026 年已形成了清晰的分层协作关系，而非替代关系。核心问题不再是"选哪个"，而是"每层用哪个"。

## 对比维度

| 维度 | 向量搜索（传统 RAG） | Graph RAG | 知识编译（LLM Wiki） |
|------|---------------------|-----------|-------------------|
| **合成时机** | 查询时合成 | 查询时合成 | 摄入时合成 |
| **数据结构** | 向量索引（块） | 图+向量混合索引 | 结构化 Wiki 页面 |
| **知识累積** | 无，每次重新检索 | 图谱可增量更新 | 每篇新资料丰富已有页面 |
| **多跳推理** | 弱，依赖语义相似度 | 强，图遍历+语义 | 中，依赖交叉链接 |
| **准确率提升** | 基准 | 复杂查询 +20-30% | 事实查询更高 |
| **扩展上限** | 数百万文档 | 数百万节点+边 | ~100-200 页（合成上限） |
| **适合内容** | 任意文本 | 实体关系丰富的语料 | 稳定、核心知识 |
| **失败模式** | 检索噪声、遗漏上下文 | 图构建质量差 | 静默漂移（需溯源） |

## 核心区别

### 1. 合成发生在什么时候？

```
向量搜索： 查询 → 检索原始块 → LLM 合成 → 答案
Graph RAG：查询 → 图检索+语义检索 → LLM 合成 → 答案
知识编译： 资料 → LLM 提前编译 → 查询 → 读预制品 → 答案
```

### 2. 知识如何处理？

```
向量搜索：原始文本分块 → 向量化 → 查询匹配相似块
Graph RAG：实体提取 → 建图 → 向量+结构双重检索
知识编译：LLM 理解 → 结构化 Wiki 页面 → 交叉链接
```

## 2026 年最佳实践：分层架构

不选边站，而是按内容稳定性分层：

```
查询路由层（基于查询类型） [[index]]
  ├── 稳定核心知识 → 知识编译（LLM Wiki）
  │   └── 例：本知识库的概念定义、方法论
  ├── 权威原始文档 → 向量搜索（传统 RAG）
  │   └── 例：PDF 论文、法律合同、财务记录
  └── 多跳关系推理 → Graph RAG
      └── 例：实体间关系、跨页知识推理
```

## 本项目中的组合

| 层 | 技术 | 实现 | 用途 |
|----|------|------|------|
| **第一层**（编译知识） | 知识编译 | wiki/ 结构化页面 | 概念、实体、对比、综述 |
| **第二层**（快速检索） | 向量搜索 | simple_vector_search | 定位相关 wiki 页面 |
| **第三层**（图谱遍历） | Graph RAG | graph_vector_search + graph_traverse | 多跳关系推理 |
| **降级层**（原始资料） | 传统 RAG | raw/sources/ 直接检索 | 未编译的原始文档 |

**分层协作示例**：
1. 用户问"Transformer 和向量搜索的关系" → Graph RAG 遍历图谱 → 找到关联链
2. 用户问"什么是注意力机制" → 知识编译直接返回概念页
3. 用户问某篇论文细节 → 向量搜索检索原始 raw/ 文档
