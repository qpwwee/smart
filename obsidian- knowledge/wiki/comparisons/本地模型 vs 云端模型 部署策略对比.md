# 本地模型 vs 云端模型 部署策略对比

> 在本地大模型和小模型快速发展的 2026 年，选择本地部署还是云端 API 已成为每个 AI 开发者必须做的架构决策。

## 对比维度

| 维度 | 本地部署 | 云端 API |
|------|---------|----------|
| **成本** | 一次性硬件 $1500-5000+，电费忽略 | $0.15-3/百万 token，长期累积昂贵 |
| **隐私** | 数据不出机器 🔒 | 数据需发送到第三方 |
| **延迟** | 0 网络延迟，但受硬件算力限制 | 有网络延迟 200-500ms |
| **可用性** | 完全离线可用 | 依赖网络连接 |
| **模型大小上限** | 受 VRAM/RAM 限制（7B-70B） | 无上限（GPT-4、Claude 3.5 等） |
| **扩展性** | 受单机硬件限制 | 弹性扩展 |
| **维护** | 需自行管理模型版本、量化 | 提供商自动维护 |
| **可定制** | 可微调、量化、修改架构 | 仅提示工程可定制 |

## 适用场景决策树

```
想处理文本/代码/图像？
├── 数据敏感（医疗/法律/金融）？ → 本地部署
├── 需要海量上下文（>200K tokens）？ → 云端 API
├── 超大规模生产（>100万请求/日）？
│   ├── 有 GPU 集群 → 本地
│   └── 无 GPU 集群 → 云端
├── 只是日常查询/写作？
│   ├── 有 16GB+ 内存 → 本地 7B 足够
│   └── MacBook 低配 → 小模型本地 + 云 API 混合
└── 需要最新最强模型？ → 云端 API
```

## 本项目的选择（混合策略 → 云端推理 + 本地嵌入）

当前配置：**推理已迁移至云端，嵌入保持本地**

| 场景 | 方案 | 模型 |
|------|------|------|
| 日常 Wiki 问答 | 云端推理 | deepseek-v4-flash-free |
| 知识库维护编译 | 云端推理 | deepseek-v4-flash-free |
| 嵌入/向量搜索 | 本地推理 | qwen3-embedding:4b [[Graph RAG vs 向量搜索 vs 知识编译]] |
| 大上下文综合分析 | 云端推理 | deepseek-v4-flash-free |

> 📝 **2026-06-09 变更**：本地推理模型（`gemma4:e4b`, `gpt-oss:20b`, `gemma4-cn`）已全部卸载。推理转为云端统一使用 `deepseek-v4-flash-free`，嵌入模型从 `qwen3-embedding:0.6b` 升级至 `4b`。

**选择理由**：
- 隐私优先：知识库内容不出本地（嵌入+检索全在本地完成）
- 云端推理质量更高：deepseek-v4-flash-free 能力远超本地 26B 模型
- 节省本地资源：不再需要常驻 9-13GB 的大模型，释放内存给嵌入服务
- 嵌入模型本地化：向量检索仍完全离线，不泄露查询内容

## 2026 年趋势

2026 年 SLM（小语言模型）已能胜任 80% 企业工作负载：
- **Phi-4 14B** 在 MATH 基准击败 o1-mini
- **Qwen 3 系列** 1.7B-30B 覆盖全场景
- **Gemma 3 27B** 128K 上下文，QAT 量化后可跑在 RTX 3090

**行业最佳实践**：混合架构 — SLM 处理 80% 请求，大模型/云端处理 20% 复杂任务。
