## OpenCode API Bridge 构建

### 核心成果
1. **OpenCode API Bridge** — Node.js 桥接服务器（端口 11555），将 OpenAI/Ollama 兼容 API 格式翻译为 OpenCode 内部协议（通过 @opencode-ai/sdk）
   - `POST /v1/chat/completions` — OpenAI 兼容聊天接口 → 代理到 OpenCode 当前模型（deepseek-v4-flash-free）
   - `POST /api/chat` — Ollama 原生格式聊天 → 代理到 OpenCode
   - `POST /v1/embeddings` — 嵌入向量（代理到本地 Ollama qwen3-embedding:0.6b，1024 维）
   - `GET /v1/models` — 模型列表
   - `GET /health` — 健康检查

2. **ai-auto-link 插件重新配置** — 从 ollama 模式（gemma4-cn:latest）切换为 cloud 模式，指向 bridge：
   - apiMode: local → cloud
   - cloudApiUrl: http://localhost:11555/v1
   - llmModel: deepseek-v4-flash-free

3. **vault-health-checker 插件适配** — 修改硬编码常量：
   - base URL: `http://localhost:11434` → `http://localhost:11555`（指向 bridge）
   - 模型名: `gemma4-cn:latest` → `deepseek-v4-flash-free`

4. **LaunchAgent 自动启动** — `~/Library/LaunchAgents/com.opencode.bridge.plist`，登录时自动启动 bridge

### 关键发现
- @opencode-ai/sdk 提供了便捷的 Python/Node SDK 来接入 OpenCode 后台（端口 4096），支持 session/prompt/messages API
- vault-health-checker 没有 SettingTab，所有配置硬编码在 main.js 中编译为常量 `I`（URL）和 `R`（模型名）
- Bridge 的 `/api/chat` 端点早期出现超时问题，原因是 `node -e "import(...)"` 方式启动时模块加载异常；直接用 `node server.js` 正常
- 向量嵌入仍走本地 Ollama（qwen3-embedding:0.6b），因为 OpenCode 自身没有嵌入 API
